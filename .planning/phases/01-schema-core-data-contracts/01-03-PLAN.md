## Phase Goal

**As a** RoadTwin operator running the dev stack, **I want to** submit a road report from a browser page and immediately see it listed back with its GPS accuracy and `unverified` status, **so that** the seven-entity data contract every later intelligence phase depends on is proven real and wired before any intelligence code is written.

<objective>
Close the Walking Skeleton loop with a real browser interaction: a minimal React 19 + Vite + TypeScript frontend whose single page posts a report to the FastAPI skeleton endpoint and renders the persisted result, plus the documented local run command that exercises the whole stack.

This is deliberately **not** the citizen reporting UI. No image upload, no map, no geolocation capture, no styling ambition — those are INGT-01 (Phase 2) and PMAP-01 (Phase 7). The page exists to prove the wire is live.

Purpose: makes SCHM-03 (`unverified` arrival status) and SCHM-04 (accuracy radius stored alongside coordinates) observable by a human rather than only by a test assertion.
Output: `frontend/` scaffold, one page, one typed API client, `README.md` run instructions.
</objective>

  - On submit: call `createReport`, prepend the returned report to local state (do not refetch the whole list — the returned object is the proof the round trip worked), clear the error, and re-enable the form. On throw, set the error message and leave the entered values in place.
