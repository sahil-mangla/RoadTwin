`backend/alembic/env.py` — per 01-RESEARCH.md Pitfalls 2 and 3:
  - `from backend.models import Base` and set `target_metadata = Base.metadata`.
  - `from backend.core.config import settings`, then `config.set_main_option("sqlalchemy.url", settings.database_url_sync)`. The asyncpg URL must never reach Alembic — `engine_from_config()` cannot drive an async-only driver.
  - Import `from geoalchemy2 import alembic_helpers` and pass `include_object=alembic_helpers.include_object`, `process_revision_directives=alembic_helpers.writer` and `render_item=alembic_helpers.render_item` into `context.configure()` in **both** `run_migrations_offline()` and `run_migrations_online()`. Omitting any of the three makes autogenerate mis-handle geometry columns and their spatial indexes.
  - `run_migrations_online()` builds a sync engine with `engine_from_config(..., prefix="sqlalchemy.", poolclass=pool.NullPool)` and runs migrations inside `with context.begin_transaction()`.

`backend/alembic/versions/0001_initial_report_schema.py` — hand-authored with `revision = "0001"` and `down_revision = None`:
  - `upgrade()` first calls `op.execute("CREATE EXTENSION IF NOT EXISTS postgis;")`. This must precede every other statement — the `geometry` type does not exist until the extension is installed.
  - Then create the Postgres enum type `report_status` with values `unverified`, `corroborated`, `evidence_confirmed`, `rejected`, binding it to a `sa.Enum(..., name="report_status", create_type=False)` reference so the table creation does not attempt a second `CREATE TYPE`.
  - Then create the `report` table with the 13 columns Plan 01 defined, using `geoalchemy2.alembic_helpers.create_geospatial_table` (or `op.create_table` with a `geoalchemy2.Geometry` column rendered through the helpers) so the `location` column and its GiST spatial index are emitted as geospatial operations rather than a plain column. `id` is `sa.Uuid` primary key; `status` is NOT NULL with server-side default `'unverified'`; `created_at` is `timezone=True` with `server_default=sa.func.now()`.
  - `downgrade()` drops the `report` table via the matching geospatial drop helper, then drops the `report_status` enum type. Deliberately do **not** drop the `postgis` extension — `CREATE EXTENSION IF NOT EXISTS` makes re-upgrade idempotent, and dropping it would cascade into anything else in the database. Note that reason in a comment.

Apply it for real: `alembic -c backend/alembic.ini upgrade head` against the running compose service. Generating the file is not sufficient — the live schema must exist.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/HTTP client → `/api/skeleton/reports` | Untrusted JSON now reaches a live, unauthenticated route. |
| Alembic process → PostgreSQL | DDL execution with elevated effect; a wrong driver or missing extension silently corrupts the schema shape. |
| FastAPI → PostgreSQL | All reads and writes traverse the ORM layer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `POST /api/skeleton/reports` body | medium | mitigate | The endpoint accepts only `ReportCreate`; FastAPI returns 422 on out-of-range latitude/longitude or negative accuracy (ASVS V5). |
| T-01-02 | Tampering | `report.location` SRID / axis order | medium | mitigate | `backend/tests/test_report_geometry.py` asserts `ST_Y`/`ST_X` match the submitted latitude/longitude and that `ST_SRID` is 4326 against the real PostGIS instance. |
| T-01-03 | Tampering | query construction in `backend/routes/skeleton.py` | high | mitigate | The route touches the database only through `ReportRepository`; no SQL text is assembled in the route. Re-checked by the interpolated-SQL grep gate carried from Plan 01. |
| T-01-07 | Denial of Service | unauthenticated skeleton router | low | mitigate | Router mounted only when `settings.skeleton_routes_enabled`; startup logs a warning; CORS restricted to the two localhost Vite origins. Rate limiting is INGT-03 in Phase 2. |
| T-01-08 | Elevation of Privilege | client-supplied `status` on report creation | medium | mitigate | `status` is absent from `ReportCreate`, so a client cannot self-declare `evidence_confirmed`; arrival status is always the `unverified` model default (SCHM-03, PITFALLS.md Pitfall 1). Asserted in Task 2's acceptance criteria. |
| T-01-09 | Tampering | Alembic pointed at the wrong driver or an un-extended database | medium | mitigate | `env.py` reads `settings.database_url_sync` only and contains no asyncpg reference (grep-gated); revision `0001` installs PostGIS before any geometry DDL; the round-trip test proves down-and-up is clean. |
</threat_model>
