## Phase Goal

**As a** RoadTwin operator running the dev stack, **I want to** submit a road report from a browser page and immediately see it listed back with its GPS accuracy and `unverified` status, **so that** the seven-entity data contract every later intelligence phase depends on is proven real and wired before any intelligence code is written.

> This plan extends the running skeleton with the remaining six entities so that the *full* seven-entity chain — not just Report — becomes reachable. Plan 05 makes that chain observable in the browser.

<objective>
Complete the locked data model: the six entities beyond Report, their foreign-key relationships, their repository mutability contracts, their Pydantic contracts, and the migration that creates them in the live PostGIS database.

Every field list here comes verbatim from `.planning/reference/RoadTwin-Architecture-Input-Spec.md` §4 as resolved by `01-RESEARCH.md`'s RESOLUTION ADDENDUM (D-09). No field is invented beyond the additive UUID primary keys (D-05), the Detection status column (SCHM-03), the derived geometry columns, and Prediction's `method` column — each of which the addendum justifies explicitly.

Purpose: SCHM-01 (all seven distinct and related), SCHM-02 (append-only enforcement made structural for the three time-series entities, per D-08), SCHM-03 (Detection's half of the status lifecycle).
Output: Six model modules, seven concrete repositories, entity contracts, migration `0002`, and the SCHM-01 / SCHM-02 test files named in `01-VALIDATION.md`.
</objective>
