## Phase Goal

ROADMAP Phase 2 `**Goal:**` (verbatim): *Citizens can submit road-damage reports that are
safely and durably captured, attributable to a lightweight identity, and protected from spam
and evidence-score gaming.*

**⚠ Format discrepancy:** MVP mode is on but this goal is not in the required
`**As a** … **I want to** … **so that** …` form. Not invented here — run `/gsd mvp-phase 2`
if a formal user story is required. See plan `02-01` for the same notice.

<objective>
Refine the working, attributed submission path so it is protected from spam and
evidence-score gaming. Three independent checks run before any image byte is read: a rolling-window
count keyed on the device identity, the same count keyed on the client IP, and an
identity-agnostic spatial cooldown against the existing `report.location` column. Any breach
returns 429 with `Retry-After`.

Purpose: INGT-03, the last backend requirement of this phase, and the item
`research/PITFALLS.md` flags as something that "must exist before real citizen traffic," not a
deferrable stub. After this plan a citizen can still submit exactly as before — but an
automated flood cannot.

Output: `backend/services/ingestion/rate_limit.py` and its wiring into `submit_report`, plus
`backend/tests/test_rate_limit.py`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| citizen browser → POST /api/reports | The request supplies both identity-bearing cookie and, indirectly, the source IP the limiter keys on; both are attacker-influenceable. |
| reverse proxy → FastAPI | `request.client.host` is the proxy's address unless a trusted-proxy policy exists; a forwarded header would be client-controlled. |
| rate-limit counters ↔ Report insert | The check and the write must not diverge on a crash mid-request. |
