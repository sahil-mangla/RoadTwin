## Phase Goal

ROADMAP Phase 2 `**Goal:**` (verbatim): *Citizens can submit road-damage reports that are
safely and durably captured, attributable to a lightweight identity, and protected from spam
and evidence-score gaming.*

**⚠ Format discrepancy:** MVP mode is on but this goal is not in the required
`**As a** … **I want to** … **so that** …` form. Not invented here — run `/gsd mvp-phase 2`
if a formal user story is required. See plan `02-01` for the same notice.

<objective>
Put a real citizen in front of the ingestion path built in plan 02-02. A browser page attempts
geolocation on load, shows the result as a draggable pin on a Leaflet map for confirmation,
accepts a photo and an optional description, validates before firing, and posts multipart form
data to `POST /api/reports` — then shows the citizen that their report was recorded.

Purpose: INGT-01's citizen-facing half. This plan runs in the same wave as plan 02-03 because it
touches only files under `frontend/`, with zero overlap against the backend files 02-03 modifies.
It depends only on plan 02-02's endpoint contract; the identity cookie (02-03) and rate limiting
(02-04) attach to the same request transparently as they land.

Output: `LocationPicker.tsx`, `ReportSubmitPage.tsx`, two new client functions, the Leaflet
dependencies, and real navigation in `App.tsx` so both pages are reachable.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| citizen browser → FastAPI `/api/reports` | The browser composes the multipart body; nothing it sends is trusted, and server-side Pydantic validation remains the sole authority. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-02-21 | Tampering | client-side `validateReportDraft` | medium | mitigate | The client check exists only to avoid firing a request that cannot succeed; `ReportCreate`'s Pydantic constraints remain the sole validation authority server-side, and `noValidate` keeps HTML attributes from implying otherwise.
