## Phase Goal

The ROADMAP `**Goal:**` line for Phase 2 reads, verbatim:

> Citizens can submit road-damage reports that are safely and durably captured, attributable
> to a lightweight identity, and protected from spam and evidence-score gaming.

**⚠ Format discrepancy (surfaced, not resolved):** MVP mode is enabled for this phase, but the
ROADMAP goal is **not** in the required `**As a** … **I want to** … **so that** …` user-story
form. Per the MVP planning rules the planner must not invent a user story. Run
`/gsd mvp-phase 2` if a formal three-slot user story is required before execution; the
vertical-slice task ordering below is already MVP-shaped and does not depend on it.

<objective>
Stand up the two prerequisites that every other plan in this phase has no fallback for: the
MinIO object-storage service (02-RESEARCH.md Environment Availability lists it as
"Missing dependencies with no fallback") and the four new Python packages the ingestion path
needs. Extend the single `Settings` class with every configuration knob this phase's
Claude's-Discretion values live in, and register the pytest skip-guard fixture that lets
object-storage tests degrade gracefully on a machine without Docker running.

can run a single acceptance check until MinIO is reachable and `minio`/`Pillow` are importable.

("docker-compose.yml MinIO service addition is scheduled as an early/Wave-0-equivalent task").
It deliberately ships no user-facing behavior; the first real end-to-end slice is plan 02-02.

Output: a running object store, four audited dependencies installed, one extended Settings
class, one pytest fixture + marker, and README run instructions.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer workstation → PyPI | Untrusted third-party code enters the build at `pip install` time. |
| FastAPI process → MinIO (S3 API) | Object-storage credentials cross this boundary; in dev it is plaintext HTTP on localhost. |
| environment/`.env` → process config | The cookie-signing secret enters the process here; a defaulted value makes every downstream signature forgeable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-SC | Tampering | `pip install` of minio / Pillow / python-multipart / itsdangerous | high | mitigate | Task 1 is a blocking-human legitimacy checkpoint verifying each PyPI project's upstream repository before task 2 installs anything; `workflow.auto_advance` is ignored for it. `exifread` (the one package with an unconfirmable repo URL) is dropped entirely in favour of Pillow's built-in EXIF path. |
| T-02-07 | Information Disclosure | `Settings.device_id_cookie_secret` | critical | mitigate | No literal default; `resolve_device_id_cookie_secret()` mints an ephemeral per-process secret and logs a warning naming `DEVICE_ID_COOKIE_SECRET`. A shared/hardcoded secret would let anyone forge a signed device identity (see T-02-01 in plan 02-03). |
| T-02-09 | Information Disclosure | MinIO root credentials in `docker-compose.yml` | medium | accept | Dev-only defaults (`roadtwin` / `roadtwin_dev_secret`) are overridable via `MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD`; `backend/.env.example` documents that a deployment must override them. Accepted at ASVS L1 for a local compose stack; breadcrumb to `/gsd-secure-phase` for deployment hardening. |
| T-02-10 | Information Disclosure | MinIO transport (`minio_secure=False` in dev) | low | accept | Plaintext S3 traffic over localhost only. `Settings.minio_secure` is the single switch a deployment flips to TLS; no application code changes. Server-side bucket encryption is an explicit OPT-OUT in `COVERAGE.md` for v1. |
</threat_model>
