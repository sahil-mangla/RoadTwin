## Phase Goal

ROADMAP Phase 2 `**Goal:**` (verbatim): *Citizens can submit road-damage reports that are
safely and durably captured, attributable to a lightweight identity, and protected from spam
and evidence-score gaming.*

**⚠ Format discrepancy:** MVP mode is on but this goal is not in the required
`**As a** … **I want to** … **so that** …` form. Not invented here — run `/gsd mvp-phase 2`
if a formal user story is required. See plan `02-01` for the same notice.

<objective>
Close the three loose ends the earlier slices deliberately deferred, each of which a source
artifact names and none of which is optional. First, the EXIF-GPS candidate path: CLAUDE.md's
stack section and D-07's own justification both rest on the server inspecting photo metadata to
"auto-populate geolocation ... when the citizen doesn't manually drop a pin", and this is where
that capability lands — routed through D-10's confirmation UI, never around it. Second, the image
format allow-list gets verified against real files so 02-RESEARCH.md's Open Question 2 on HEIC is
answered by a test rather than a guess. Third, `prune_old_attempts` from plan 02-04 becomes an
exposed, tested operation so Pitfall 2's unbounded-growth concern has a real answer inside this
phase.

Purpose: a refinement slice. After it a citizen whose browser blocks geolocation still gets a
useful starting pin from their own photo, and the operator has a documented answer for table
growth and format support.

Output: `extract_exif_gps`, the `POST /api/reports/exif-gps-probe` endpoint, the frontend
candidate-pin offer, a pruning test, and documentation.
</objective>
