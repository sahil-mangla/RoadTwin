## Phase Goal

ROADMAP Phase 2 `**Goal:**` (verbatim): *Citizens can submit road-damage reports that are
safely and durably captured, attributable to a lightweight identity, and protected from spam
and evidence-score gaming.*

**⚠ Format discrepancy:** MVP mode is on but this goal is not in the required
`**As a** … **I want to** … **so that** …` form. Not invented here — run `/gsd mvp-phase 2`
if a formal user story is required. See plan `02-01` for the same notice.

<objective>
Deliver the phase's first real vertical slice: a citizen's photo + coordinates go in over HTTP
and come back out as a durable Report row whose image is a retrievable object in MinIO. This
is the thinnest end-to-end path that a real person can exercise (via the API now, via the
browser page in plan 02-05) — identity attribution lands in plan 02-03 and spam throttling in
plan 02-04, both as refinements that wrap this same path.

Purpose: INGT-01 and INGT-04 in one slice. Splitting "the endpoint" from "the storage" would
produce two half-plans neither of which a user could exercise; splitting identity/rate-limiting
out keeps this plan inside its context budget and keeps each later plan a genuine refinement
rather than a layer.

Output: `backend/services/ingestion/upload.py`, `backend/routes/reports.py` with
`POST /api/reports` and `GET /api/reports/{report_id}/image-url`, the router mounted in
`backend/main.py`, and two new test modules covering both requirements.
</objective>

<assumption_delta_decision>
`gsd-tools query assumption-delta scan 2` returned `detected: true` with one `optional`-kind
signal: INGT-01's *"…timestamp, and **optional** description…"*.

**Decision: add alongside, do not promote.** `Report.description` already exists as a nullable
`sa.Text` column from Phase 1, and `ReportCreate.description` is already
`Field(default=None, max_length=2000)`. Nothing needs promoting from required to optional — the
optionality is pre-existing and correct. The signal is satisfied by declaring the multipart form
field as `description: str | None = Form(default=None)` alongside the two required coordinate
fields, so omitting it yields a 201 with a null description rather than a 422.

Consequence for task 1's tests: the happy-path test sends a description and
`test_submit_report_success` asserts it round-trips, while the invalid/boundary tests omit it
entirely and must still reach 201 (or 422 for the coordinate reason only, never for a missing
description). Do not add a `min_length` or a non-empty check to `description`.
</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| citizen browser → POST /api/reports | Untrusted multipart body: arbitrary binary content, arbitrary form field values, arbitrary filename. |
| FastAPI process → MinIO | The object key crosses here; a client-influenced key would let a caller address or overwrite another report's object. |
| MinIO → anyone holding a presigned URL | A leaked or long-lived URL grants read access to a citizen's photo and its implied location. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-02 | Denial of Service | `validate_and_normalize_image` in `backend/services/ingestion/upload.py` | high | mitigate | Bounded `upload.read(max_upload_bytes + 1)` before any decode, then Pillow `verify()` with `DecompressionBombWarning` promoted to an error via `warnings.simplefilter`, so a small file with a huge declared pixel count is a hard 422 rather than a logged warning. Asserted by `test_reject_oversized_and_corrupt_image` and `test_reject_decompression_bomb_image`. |
| T-02-03 | Tampering | `generate_object_key` / `put_report_image` | high | mitigate | The key is `reports/{server-generated report UUID}.{server-determined extension}` — `upload.filename` is never read into it. `ReportCreate.image_path` additionally enforces `max_length=256` and the `^reports/<uuid>\.(jpg\|png)$` pattern as defense in depth (D-08, closes `01-REVIEW.md` WR-02). `put_report_image` calls `stat_object` first and raises 409 rather than overwriting an existing object. |
| T-02-06 | Information Disclosure | `get_report_image_url` / `get_presigned_image_url` | high | mitigate | Access is only ever granted through `presigned_get_object` with a `minio_presigned_url_ttl_seconds` (900 s default) expiry, minted per request. No URL is persisted on the Report row, embedded in `ReportRead`, or cached. `COVERAGE.md` records `set_bucket_policy` as an explicit OPT-OUT so the bucket never becomes anonymously readable. |
| T-02-11 | Denial of Service | MinIO reachability from `submit_report` | medium | mitigate | Connection/S3 failures are converted to an explicit 503 with a clear detail rather than a 500 traceback; `ensure_bucket()` at startup is wrapped so an object-store outage cannot prevent the API from booting. |
| T-02-12 | Tampering | client-supplied `status` / `timestamp` / `verification_score` form fields | medium | mitigate | `submit_report`'s signature declares no such parameters, so FastAPI discards them; `test_submit_report_timestamp_is_server_generated` proves a client-sent `timestamp` is ignored. Follows Phase 1's T-01-08 precedent. |
| T-02-08 | Information Disclosure | EXIF metadata retained inside the stored image object | medium | accept | The citizen's photo is stored as uploaded (byte-identical when no rotation is needed) to preserve evidence integrity, which means original EXIF — including any embedded GPS and device identifiers — is retained. Objects are reachable only via short-lived presigned URLs (T-02-06), never publicly. Accepted for v1 at ASVS L1; breadcrumb to `/gsd-secure-phase` if a metadata-stripping derivative is ever wanted alongside the original. |
