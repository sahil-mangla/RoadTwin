## Phase Goal

ROADMAP Phase 2 `**Goal:**` (verbatim): *Citizens can submit road-damage reports that are
safely and durably captured, attributable to a lightweight identity, and protected from spam
and evidence-score gaming.*

**⚠ Format discrepancy:** MVP mode is on but this goal is not in the required
`**As a** … **I want to** … **so that** …` form. Not invented here — run `/gsd mvp-phase 2`
if a formal user story is required. See plan `02-01` for the same notice.

<objective>
Refine plan 02-02's working submission path so every report is *attributed*. A citizen who
submits gains a server-issued, cryptographically signed device identity carried in an HttpOnly
cookie, and that identity is persisted on the Report row — no account, no email, no password
(D-01, D-02). The same migration also lands the `submission_attempt` table plan 02-04 needs, so
this phase has exactly one Alembic revision to reason about.

Purpose: INGT-02. This is a refinement slice on top of 02-02's happy path, not a new layer —
after it, a real citizen can do something new (be recognised across submissions) that they
could not do before.

Output: Alembic revision `0003` applied to the live database, `Report.submitter_identity_key`,
`SubmissionAttempt` + its repository, `backend/services/ingestion/identity.py`, and the
`get_device_identity` dependency wired into `POST /api/reports`.
</objective>

    Never raise from this function and never return a 4xx: a bad cookie is not a client error, and

    cookies-blocked prohibition forbids.

    max_age=settings.device_id_cookie_max_age_seconds, path="/")`. `httponly=True` and
    `samesite="lax"` are unconditional (ASVS V3 cookie attributes); `secure` is
    settings-driven so local HTTP dev works while a deployment flips one flag.

    `read_or_mint_device_id`, call `set_device_cookie` only when a new value was minted, and

    keeps the signature a server-side concern.

    — the identity is never a client-supplied value, exactly as `status` and `timestamp` are not.
    Do not add the identity to `ReportRead` or any other response model: the privacy prohibition
    forbids citizen-visible attribution of a device identifier, and `ReportRead`'s field set must

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| citizen browser → `rt_device_id` cookie | The client holds and returns the identity bearer token; it must be unforgeable and unreadable to page scripts. |
| environment → signing secret | A defaulted or shared secret collapses the whole boundary above. |
| request → `Report.submitter_identity_key` | The persisted attribution must derive from a verified signature, never from a raw client claim. |
